# Agent Note: 独立解析器修复的对照证据

Status: implemented

## Problem

vLLM #55195 已有通用解析器修复 PR，仅凭 issue 标题继续开发会重复贡献。
独立实现的源码复现又不足以证明真实流式服务覆盖了分组边界，需要能复核的
前后证据，同时避免把小模型解析器检查写成原生大模型评测。

## Decision

上游补丁在固定版本的本地分支开发，本仓保存完整 patch、测试日志、GPU SSE、
环境与 tokenizer 版本、复现脚本、公开草稿和人工台账。公开补丁仅含两个生产
文件与两个正式测试文件；本地决策笔记从上游补丁排除，镜像到私有证据目录。
原始日志、JUnit 和 patch 保留字节；`.gitattributes` 仅对本案例这三类证据关闭
空白诊断，避免改写失败输出或破坏 patch 的空行上下文。代码与文档仍检查空白。

旧源码与修复使用同一组二十三项测试；对照只切换生产文件，测试文件不变。
GPU 请求通过结构化输出和允许 token IDs 形成含起始 ID 的分组 delta，必须同时
观察结束 ID、完整 reasoning 与最终回答。没有命中这些条件的探索请求不作为
成功证据。小 Qwen 显式选用解析器，原生 ERNIE/HY4 tokenizer 另由正式测试验证。

人工台账标记为待审阅，公开草稿不自动发布。现有 #55210/#56262 与本补丁互补；
发布前刷新分工与 diff，避免重复工作。此策略延续
[私有贡献雷达](../architecture/2026-10-04-contribution-radar.md) 的证据与授权边界。

## Alternatives considered

- 只保存源码 probe：成本最低，但无法观察真实 HTTP/SSE 分组和解码行为。
- 用原生大模型完整生成评测：代表性更强，但本机 6 GiB 显存不适合这两个模型；
  保存原生 tokenizer 测试及小模型服务验证，并明确剩余模型评测边界。
- 只公开评论、暂不准备补丁：能先沟通，但缺少可审阅的具体改动；先完成私有
  证据与补丁，再展示简短英文正文供用户确认。

## Consequences

- 旧源码五项失败、十八项通过，补丁二十三项通过；两个 parser 的四份 GPU
  SSE 均覆盖目标边界，修复后不再残留起始标记，完整 pre-commit 检查通过。
- 独立审查发现两处正常引用截断风险，已增加输出开头限制和对应回归测试。
- 保存 native wheel 与 Python 源码不同 commit 的事实，不把安装等同于完整源码构建。
- 维护代价是固定证据占用私有仓空间；它们保留验证时事实，后续结果新增记录。
- agent 检查不替代 vLLM 要求的人类逐行审阅与相关测试，草稿不承诺关闭整个 issue。
