# Agent Note: 独立解析器的分组起始标记

Status: implemented

## Problem

vLLM #55195 的两个开放 PR 修改基础解析器与 Olmo3，Ernie45 和 HYV4 的独立流式
方法仍残留起始标记。同一组二十三项正式测试在旧源码上五项失败、十八项通过；
两种解析器的真实 GPU 流式响应也残留标记。

## Decision

两种解析器仅在此前输出为空白、当前 delta 以起始结构标记开头时剥除标记。
Ernie 额外要求此前没有起始或结束 token ID，随后沿用原有回答包装处理；HYV4
只修起始标记和正文同到、没有结束标记的分支。文本标记已被过滤时保持原文。
首次 delta 中的普通引用、隐式 reasoning 后的引用及后续正文中的字面标记保留。

测试复用 Ernie 现有文件；HYV4 没有现有专用文件，新增对应小型套件。
测试使用真实模型 tokenizer，部分 case 将起始 token 标为 special，验证解码
文本隐藏标记但 ID 仍存在的路径。GPU 验证用 Qwen3-0.6B、约束输出和八 token
流式间隔形成真实分组输入，保存 token IDs 与完整 SSE，而非只检查请求参数。
Python 源码固定 bd42276；原生扩展使用 CUDA 13 官方 f98d1fc 预编译包。

## Alternatives considered

- 只修基础解析器：改动集中，但两个独立流式方法不会调用该实现，且与现有 PR 重复。
- 重构所有解析器为同一状态机：能统一契约，但超出问题范围并增加评审成本。
- 仅按起始 ID 做 split：能解决残留，但会截断省略起始标记后的正常引用。独立审查
  用真实 tokenizer 复现两处回归，因此限制到输出开头的可见结构标记。

## Consequences

- 二十三项正式测试全部通过；旧源码五项失败均为分组起始标记残留。两种解析器
  的 GPU 前后对照均确认起始 ID 与正文同 chunk，结束 ID 实际生成；修复后移除
  标记，保留全部 reasoning 正文与最终回答。四文件完整 pre-commit 检查通过。
- 代价是两份独立实现各保留局部条件；此次不统一解析器结构。
- 真实 GPU 验证是小 Qwen 显式选择解析器的服务回归，不是原生 ERNIE/HY4 大模型
  生成质量评测，也不覆盖 speculative decoding 或所有标记组合。
- Ernie response-end 索引错误已有 #48386，end-token 延迟问题另有工作，本次不修。
- 本笔记留在本地副本并镜像到私有调查记录，不加入公开上游补丁。公开 PR 仍要求
  人类理解、逐行审阅和运行相关测试，不能据 agent 检查宣称已满足。
